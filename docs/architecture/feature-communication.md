# Use case, события и стримы

## Когда открывать

- Нужно выбрать формат взаимодействия между фичами.
- Нужно понять, нужен ли `Stream`.
- Нужно решить, как оформить публичный контракт вместо прямого импорта реализации.

## Рабочий дефолт

Обычно хватает:

- BLoC
- coordinator
- query или command интерфейсов
- иногда observe-контрактов

Use case можно использовать как:

- command - "сделай что-то"
- query - "верни что-то"
- observe - "дай поток изменений"

Полезнее не слово "use case", а правило:

> между фичами общаемся через маленькие публичные контракты

Внутри такой контракт может быть command, query или observe.

## Когда stream не нужен

Стримы не нужны по умолчанию.

Примеры:

- если auth меняется, coordinator или guard может просто перестроить flow
- если данные нужны только на одном экране, их можно грузить on-enter через use case

## Когда stream оправдан

`Stream<T>` имеет смысл только если нужен live shared state:

- несколько потребителей
- открытый UI должен обновляться сам
- app shell должен автоматически реагировать

Если этих признаков нет, лучше оставить query или command и не усложнять контракт.
