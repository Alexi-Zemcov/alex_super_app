# ТЗ: Flutter Quiz, аналог web проекта лежашего по пути /Users/jf1303/projects/pets/flutter-coach/quiz-app

## Summary

- Разработать Flutter-приложение, максимально повторяющее текущее поведение веб-версии: офлайн-квиз по Flutter/Dart с локальным набором вопросов, прогрессом, избранным, темами, билетами, блицем, марафоном и экраном ошибок.
- Источник данных в `v1`: локальный bundled dataset без обязательного backend. Текущий объём: `117` вопросов, `14` категорий, `12` билетов по `10` вопросов, последний билет на `7` вопросов.
- Язык интерфейса: русский. Базовый UX: мобильный single-column, карточки, прогресс-бары, 3 темы оформления (`dark`, `white`, `black`).
- Архитектурный ориентир для Flutter: feature-first + Clean Architecture, где доменный слой не зависит от UI, локального хранилища и аналитики.

## Domain Contracts

- `QuestionKey`: строковый ключ вопроса в формате `"{category}|{question}"`. Это нужно для полной поведенческой совместимости с текущим проектом.
- `QuizQuestion`: `key`, `category`, `question`, `options[4]`, `correctIndex`, `explanation`.
- `Ticket`: `id`, `questions`.
- `Topic`: `id`, `name`, `questions`.
- `QuizMode`: `ticket`, `blitz`, `topic`, `marathon`, `errors`, `favorites`.
- `QuizAnswer`: `questionKey`, `category`, `selectedIndex`, `isCorrect`, `timedOut`.
- `QuestionStats`: `correctAttempts`, `totalAttempts`.
- `QuizSession`: `mode`, `context`, `currentQuestions`, `answers`, `currentIndex`.
- `ThemePreference`: `dark | white | black`.
- Обязательные интерфейсы домена:
- `QuestionRepository`: загрузка всех вопросов, генерация билетов, генерация тем.
- `ProgressRepository`: чтение/запись статистики, избранного, активной ticket-session, темы.
- Ключевые use cases:
- `GetHomeProgress`, `GetTickets`, `GetTopics`, `StartTicketQuiz`, `ResumeTicketQuiz`, `RestartTicketQuizWithReset`, `StartBlitz`, `StartTopicQuiz`, `StartMarathon`, `StartErrorsQuiz`, `StartFavoritesQuiz`, `SubmitAnswer`, `GoToAnsweredQuestion`, `GoToNextUnansweredQuestion`, `ToggleFavorite`, `GetResults`, `RetryCurrentMode`, `LoadTheme`, `SetTheme`.

## Functional Requirements

- `Контент:` все вопросы хранятся локально; у каждого вопроса обязательны категория, текст, 4 варианта ответа, индекс правильного ответа и пояснение.
- `Порядок вопросов:` во всех режимах сохраняется исходный порядок вопросов, кроме `blitz`, где выбираются случайные `10` вопросов. Варианты ответов перемешиваются во всех режимах.
- `Главный экран:` показывать счётчики и прогресс-бары по вопросам, билетам и темам, а также кнопки перехода в режимы `Билеты`, `Блиц`, `Темы`, `Марафон`, `Ошибки`, `Избранное`.
- `Прогресс на главном:` вопрос считается пройденным, если по нему есть хотя бы одна правильная попытка; билет/тема считаются пройденными, если по всем входящим вопросам есть хотя бы одна правильная попытка.
- `Билеты:` показывать список билетов с прогрессом `correct/total` и полосой заполнения. При входе в билет, если по его вопросам уже есть попытки, открывать модалку `Продолжить / Начать заново`.
- `Продолжить билет:` восстанавливать только незавершённую сохранённую `ticket-session` для того же билета; если session нет, начинать билет заново, но без очистки общей статистики.
- `Начать заново в билете:` удалять сохранённую session и полностью очищать статистику по вопросам этого билета.
- `Темы:` строить список по категориям; тема визуально помечается завершённой, если все её вопросы хотя бы раз решены правильно.
- `Блиц:` запускать случайные `10` вопросов с таймером `10 минут`. По окончании времени все неотвеченные вопросы помечать как неправильные в рамках текущего результата.
- `Марафон:` запускать все вопросы подряд без таймера. Для точного соответствия текущей логике resume для марафона не требуется, даже если текст интерфейса намекает на продолжение позже.
- `Ошибки:` включать вопросы, у которых `totalAttempts > correctAttempts`. Это означает “была хотя бы одна ошибка в истории”, а не “последний ответ неверный”.
- `Избранное:` показывать только вопросы, отмеченные пользователем. Если избранного нет, отображать empty state.
- `Экран вопроса:` показывать заголовок режима, номер текущего вопроса, таймер только для `blitz`, ленту номеров вопросов, текст вопроса, варианты ответа, переключатель избранного, блок пояснения и кнопку перехода дальше.
- `Ограничения в квизе:` нельзя ответить на вопрос повторно; нельзя перейти к ещё неотвеченному будущему вопросу из ленты; можно открыть текущий или уже отвеченный вопрос.
- `После ответа:` подсвечивать правильный вариант, подсвечивать выбранный неверный вариант, показывать пояснение и кнопку `Следующий вопрос`.
- `Переход дальше:` искать следующий неотвеченный вопрос после текущего, затем с начала списка; если неотвеченных не осталось, открывать результаты.
- `Результаты:` показывать процент правильных ответов, счёт `X из Y`, breakdown по категориям и кнопки `Пройти заново` и `На главную`.
- `Повтор режима:` кнопка `Пройти заново` перезапускает текущий режим без очистки накопленной статистики. Исключение только одно: сброс через модалку продолжения билета очищает stats билета.
- `Навигация:` явный выход из активного квиза должен возвращать на главный экран; при системной попытке выйти из незавершённого квиза нужно запросить подтверждение.

## Persistence And Infra

- Хранить локально: `questionStats`, `favorites`, `ticketSession`, `themePreference`.
- Сохранять `ticketSession` только для режима `ticket` и только после ответа на вопрос.
- Тема по умолчанию: `dark`. Порядок переключения тем: `dark -> white -> black -> dark`.
- Аналитика и Firebase не участвуют в доменной логике. Если подключаются в Flutter-версии, они должны быть инфраструктурной опцией, а не зависимостью domain-слоя.

- Проверить различие между `Продолжить билет`, `Начать заново` и `Пройти заново` после результатов.
- Проверить, что в `blitz` таймер завершает сессию и неотвеченные вопросы попадают в результат как неправильные.
- Проверить, что пользователь не может отвечать повторно и не может прыгать в будущие неотвеченные вопросы.
- Проверить сохранение и восстановление темы, избранного и ticket-session между перезапусками приложения.
- Проверить расчёт результатов: процент, счёт, разбиение по категориям, повтор текущего режима.

## Assumptions

- `v1` не включает авторизацию, синхронизацию между устройствами, административную панель, удалённый API и редактирование вопросов из приложения.
- При расхождении между текстом интерфейса и фактической логикой приоритет у текущего поведения кода, потому что запрос был “максимально как сейчас”.
- Для устойчивого доменного слоя допустимо позже заменить `QuestionKey` на явный `questionId`, но в этом ТЗ зафиксирован текущий совместимый вариант на основе `category + question`.
