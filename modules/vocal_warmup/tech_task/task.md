# ТЗ: модуль распевки и развития голоса

## 1. Контекст

Нужно реализовать модуль `vocal_warmup` для приложения Alex Super App. Модуль помогает пользователю определить комфортный вокальный диапазон и пройти короткую распевку с аккомпанементом.

Исходники для проектирования:

- дизайн экранов: `modules/vocal_warmup/tech_task/design.png`;
- текущий package: `modules/vocal_warmup`;
- standalone host уже предусмотрен в workspace как `apps/vocal_warmup_app`.

## 2. Цели продукта

Пользователь должен:

- быстро определить нижнюю и верхнюю комфортные ноты;
- увидеть свой диапазон, частоты крайних нот и примерную классификацию голоса;
- выбрать тип распевки;
- пройти упражнение сначала с голосовой подсказкой, затем самостоятельно под аккомпанемент;
- безопасно остановиться или изменить направление, когда упражнение подходит к границе диапазона.

## 3. MVP scope

В MVP входят:

- flow определения диапазона;
- экран результата диапазона;
- выбор типа упражнения;
- режим распевки с двумя упражнениями:
  - `Мычание`: паттерн `1-2-1`;
  - `Тра-та-та`: паттерн `1-2-3-2-1`;
- два режима прохождения:
  - `Поём с голосом`;
  - `Поём самостоятельно`;
- проигрывание аккомпанемента;
- голосовая/мелодическая подсказка в режиме `Поём с голосом`;
- предупреждение при приближении к верхней или нижней границе диапазона;
- сохранение последнего определённого диапазона локально.

Не входит в MVP:

- оценка качества пения, скоринг и детальная статистика;
- аккаунты, синхронизация, backend;
- редактор упражнений;
- полноценная настройка тембра/инструментов, кроме минимальных параметров, нужных для работы текущего flow.

## 4. Термины

- Диапазон - комфортный пользовательский диапазон от самой низкой до самой высокой устойчиво спетой ноты.
- Тесситура - рабочая комфортная часть диапазона. В интерфейсе MVP использовать слово `диапазон`, как в дизайне.
- Нота - музыкальная высота в формате `E2`, `C5` и т.п.
- Паттерн - последовательность ступеней относительно текущей тональной опоры упражнения, например `1-2-1`.
- Проход - один цикл упражнения на одной высоте: сначала вариант с голосом, затем самостоятельный вариант.
- Шаг - транспозиция паттерна на следующую высоту.

## 5. Пользовательские сценарии

### 5.1. Первичный запуск

1. Пользователь открывает модуль.
2. Если сохранённого диапазона нет, модуль открывает flow определения диапазона.
3. Пользователь поёт самую низкую комфортную ноту.
4. Приложение слушает микрофон, определяет устойчивую ноту и переходит к определению верхней ноты.
5. Пользователь поёт самую высокую комфортную ноту.
6. Приложение показывает экран результата диапазона.
7. Пользователь выбирает `Продолжить` и переходит к выбору упражнения.

### 5.2. Повторное определение диапазона

1. На экране результата пользователь нажимает `Заново`.
2. Приложение очищает текущий результат в памяти текущего flow.
3. Пользователь заново проходит нижнюю и верхнюю ноты.
4. После успешного определения новый диапазон сохраняется локально.

### 5.3. Выбор распевки

1. Пользователь попадает на экран `Распевка`.
2. На экране доступны карточки упражнений:
   - `Мычание`, паттерн `1-2-1`;
   - `Тра-та-та`, паттерн `1-2-3-2-1`.
3. Пользователь выбирает упражнение тапом по карточке.
4. Дополнительно поддержать свайп влево/вправо между упражнениями, как указано в исходной идее.

### 5.4. Прохождение распевки

1. Пользователь видит экран распевки.
2. Вверху доступен переключатель упражнений `Мычание` / `Тра-та-та`.
3. Отображается текущий режим:
   - `Поём с голосом`;
   - `Поём самостоятельно`.
4. В режиме `Поём с голосом` приложение играет аккомпанемент и голосовую подсказку.
5. Затем приложение переходит в режим `Поём самостоятельно`: играет только аккомпанемент, пользователь повторяет паттерн сам.
6. После пары режимов приложение транспонирует упражнение выше.
7. Когда высота приближается к верхней границе диапазона, приложение показывает предупреждение и кнопки:
   - `Выше / ниже`;
   - `Хватит`.
8. Если пользователь выбирает `Выше / ниже`, приложение продолжает упражнение в выбранном направлении.
9. Если пользователь выбирает `Хватит`, текущая сессия завершается или возвращает пользователя к выбору упражнения.
10. После верхней части упражнение должно идти на уменьшение высоты до нижней части диапазона.
11. При приближении к нижней границе показывается аналогичное предупреждение.

## 6. Экраны и UI

### 6.1. Определение нижней ноты

Состояния:

- запрос разрешения на микрофон;
- слушаем пользователя;
- нота найдена;
- ошибка или микрофон недоступен.

UI по дизайну:

- заголовок `Определение диапазона`;
- текст `Спойте самую низкую комфортную ноту`;
- декоративная волна;
- большая круглая зона с иконкой микрофона;
- индикатор `Слушаем...`;
- нижний индикатор прогресса: первый шаг активен.

Поведение:

- экран автоматически начинает слушать после получения разрешения;
- нота считается найденной, если высота стабильна в течение короткого окна;
- шум и тишина игнорируются;
- после успешного определения нижней ноты экран переходит к определению верхней.

### 6.2. Определение верхней ноты

UI аналогичен первому шагу, но текст:

- `Теперь спойте самую высокую комфортную ноту`;
- второй индикатор прогресса активен.

Поведение:

- приложение проверяет, что верхняя нота выше нижней;
- если пользователь спел ноту ниже или слишком близко к нижней, показать мягкую ошибку и продолжить слушать;
- после успешного определения перейти к экрану результата.

### 6.3. Результат диапазона

UI по дизайну:

- заголовок `Ваш диапазон`;
- две колонки:
  - `От`, нота и частота;
  - `До`, нота и частота;
- горизонтальный слайдер/диапазон;
- клавиатура с подсветкой найденного диапазона;
- карточка `Ваш тембр`;
- кнопка primary `Продолжить`;
- кнопка secondary `Заново`.

Данные на экране:

- нижняя нота, например `E2`;
- верхняя нота, например `C5`;
- частоты в Гц;
- примерная классификация голоса, например `Тенор`;
- короткое описание, например `Драматический`.

Допущение для MVP:

- `Ваш тембр` фактически означает примерный вокальный тип по диапазону. Если терминологически важно различать тембр и тип голоса, это нужно уточнить перед финальной реализацией.

### 6.4. Выбор упражнения

UI по дизайну:

- заголовок `Распевка`;
- подзаголовок `Выберите тип упражнения`;
- карточка `Мычание`, паттерн `1-2-1`;
- карточка `Тра-та-та`, паттерн `1-2-3-2-1`;
- подсказка про свайп влево/вправо.

Поведение:

- активная карточка выделяется фиолетовой рамкой и иконкой звуковой волны;
- тап по карточке открывает сессию выбранного упражнения;
- свайп меняет выбранное упражнение без обязательного перехода на отдельный экран.

### 6.5. Экран распевки

UI по дизайну:

- верхняя строка:
  - заголовок `Распевка`;
  - иконка настроек;
- segmented control для упражнений:
  - `Мычание`;
  - `Тра-та-та`;
- режим текущего прохода:
  - `Поём с голосом`;
  - `Поём самостоятельно`;
- прогресс вида `1 / 8`, `2 / 8`, `3 / 8`;
- центральная круглая визуализация:
  - в режиме с голосом показывать волну;
  - в самостоятельном режиме можно показывать пустое кольцо или реакцию на микрофон;
- direction chip `Вверх` или `Вниз`;
- паттерн крупным текстом, например `1 - 2 - 1`;
- нотный/линейный индикатор с точками паттерна;
- кнопка `Пропустить голос` в режиме с голосом;
- нижний индикатор прогресса/страниц.

Поведение:

- `Пропустить голос` пропускает голосовую подсказку и сразу запускает самостоятельный проход на той же высоте;
- переключение упражнения во время сессии сбрасывает текущую сессию выбранного упражнения;
- настройки в MVP могут открывать placeholder/bottom sheet только с доступными параметрами, если полноценный экран настроек не проектируется отдельно.

### 6.6. Предупреждение у границы диапазона

UI по дизайну:

- warning icon;
- текст:
  - `Вы близко к верхней границе диапазона`;
  - или `Вы близко к нижней границе диапазона`;
- кнопка направления `Выше / ниже`;
- кнопка `Хватит`.

Поведение:

- предупреждение показывается после завершения прохода, а не посреди звучания;
- пользователь сам подтверждает продолжение за пределы комфортной зоны текущего шага;
- `Хватит` завершает упражнение без ошибки.

## 7. Музыкальная логика

### 7.1. Определение высоты

Требования:

- использовать микрофон устройства;
- определять основную частоту голоса;
- переводить частоту в ближайшую музыкальную ноту;
- сохранять частоту и ноту для нижней и верхней границы;
- фильтровать тишину, шум и короткие случайные пики;
- показывать понятное состояние, если микрофон недоступен.

Допущения для MVP:

- стабильная нота - это нота, удерживаемая примерно 500-1000 мс;
- если несколько устойчивых нот попали в окно, выбирать медианное или наиболее продолжительное значение;
- частоты округлять до целых Гц в интерфейсе.

### 7.2. Классификация голоса

На экране результата нужно показать примерный тип голоса. MVP может использовать простую таблицу пересечения диапазонов.

Примерные категории:

- бас;
- баритон;
- тенор;
- альт;
- меццо-сопрано;
- сопрано.

Точную таблицу диапазонов и тексты описаний нужно утвердить отдельно.

### 7.3. Аккомпанемент

Каждый проход состоит из:

- трёх аккордов на пианино по схеме `1-2-1`;
- голосовой/мелодической подсказки по паттерну упражнения в режиме `Поём с голосом`;
- повторного проигрывания только аккомпанемента в режиме `Поём самостоятельно`.

Требования:

- инструмент аккомпанемента: piano;
- темп должен быть комфортным для начинающего пользователя;
- между режимами должен быть короткий понятный переход;
- звук должен воспроизводиться без заметных обрывов;
- при уходе с экрана воспроизведение останавливается.

### 7.4. Упражнения

`Мычание`:

- паттерн: `1-2-1`;
- голосовая подсказка звучит как мягкое мычание или нейтральная вокальная имитация;
- подходит для первого упражнения.

`Тра-та-та`:

- паттерн: `1-2-3-2-1`;
- голосовая подсказка должна имитировать слоги `тра-та-та`;
- используется как следующий по сложности режим.

Допущение для MVP:

- транспозиция идёт хроматически, на один полутон за шаг.

### 7.5. Границы диапазона

Текущая высота упражнения не должна неожиданно уходить далеко за найденный комфортный диапазон.

Правила:

- если следующая транспозиция приближает верхнюю ноту паттерна к верхней границе диапазона, показать предупреждение;
- если следующая транспозиция приближает нижнюю ноту паттерна к нижней границе диапазона, показать предупреждение;
- порог близости для MVP: 1-2 полутона от соответствующей границы;
- пользователь может вручную продолжить выше/ниже или остановить упражнение.

## 8. Данные и состояние

Основные domain-модели:

- `VocalRange`:
  - `lowestNote`;
  - `highestNote`;
  - `lowestFrequencyHz`;
  - `highestFrequencyHz`;
  - `detectedAt`;
- `VoiceType`:
  - `title`;
  - `description`;
  - `matchedRange`;
- `WarmupExercise`:
  - `id`;
  - `title`;
  - `syllable`;
  - `patternDegrees`;
- `WarmupSession`:
  - `exercise`;
  - `range`;
  - `direction`;
  - `currentStep`;
  - `totalSteps`;
  - `currentMode`;
- `WarmupStep`:
  - `rootNote`;
  - `patternNotes`;
  - `isNearLowerBoundary`;
  - `isNearUpperBoundary`.

Локально сохранять:

- последний успешно определённый диапазон;
- дату определения;
- выбранное последнее упражнение.

Не сохранять в MVP:

- аудиозаписи пользователя;
- историю всех тренировок;
- сырые данные микрофона.

## 9. Архитектура в workspace

`vocal_warmup` остаётся самостоятельным продуктовым модулем в `modules/vocal_warmup`.

Публичная поверхность модуля:

- один public entry point: `lib/vocal_warmup.dart`;
- наружу экспортировать только модульный descriptor/factory для shell и standalone host;
- не экспортировать `src/*`, Bloc, repositories, datasources, use cases.

Рекомендуемая структура:

```text
modules/vocal_warmup/lib/
  vocal_warmup.dart
  src/
    module/
    navigation/
    di/
    features/
      range_detection/
        presentation/
        domain/
        data/
        di/
      warmup/
        presentation/
        domain/
        data/
        di/
```

Presentation:

- route-level widgets класть в `presentation/screens/<screen_name>/<screen_name>_screen.dart`;
- screen-owned Bloc/Cubit класть рядом с экраном в `presentation/screens/<screen_name>/bloc`;
- переиспользуемые внутри feature виджеты класть в `presentation/widgets`.

DI:

- использовать provider-based DI: `ScopeModule`, `FeatureScope`, `RouteScope`, `Provider`, `RepositoryProvider`, `BlocProvider`;
- зависимости создавать в `src/di`, `features/*/di` или scope widgets;
- не собирать repositories/use cases/Bloc прямо в router, screen или widget.

Data:

- datasource отвечает только за низкоуровневое чтение/запись локальных настроек;
- repository отвечает за cache/storage policy и преобразование данных в domain-модели;
- pitch detection и audio playback лучше закрыть внутренними domain/data абстракциями, чтобы UI не зависел от деталей реализации.

## 10. Интеграции и разрешения

Требуется:

- разрешение на микрофон;
- воспроизведение звука;
- локальное хранилище для последнего диапазона.

Текущие зависимости package уже включают:

- `music_theory` - для нот, интервалов и музыкальных расчётов;
- `midi_playback` - для MIDI/аккомпанемента;
- `shared_preferences` - для локального сохранения;
- `flutter_bloc`, `provider`, `scoped_di` - для состояния и DI.

Если выбранный pitch detection требует сторонний SDK или platform channel, его нужно оформить так, чтобы продуктовая логика осталась внутри `modules/vocal_warmup`, а product-agnostic adapter при необходимости мог быть вынесен в `packages/integrations/*`.

## 11. Нефункциональные требования

- Платформы MVP: iOS и Android.
- Интерфейс должен быть минималистичным и близким к `design.png`.
- Цветовая основа: светлый фон, фиолетовый accent, мягкие серые secondary controls.
- Все тексты должны помещаться на маленьких экранах без наложений.
- Анимации волн и колец не должны мешать чтению и управлению.
- Приложение должно корректно переживать уход со страницы, сворачивание приложения и отказ в разрешении микрофона.
- Микрофонные данные и аудиозаписи не должны покидать устройство.

## 12. Ошибки и пустые состояния

Нужно предусмотреть:

- пользователь отказал в доступе к микрофону;
- микрофон недоступен;
- слишком тихий сигнал;
- не удалось устойчиво определить ноту;
- верхняя нота ниже нижней;
- нет сохранённого диапазона перед стартом распевки;
- audio playback не смог стартовать.

Для каждой ошибки нужен короткий понятный текст и действие восстановления: повторить, открыть настройки, пройти определение диапазона заново или вернуться назад.

## 13. Тестирование

Минимальный набор тестов:

- domain-тесты конвертации частоты в ноту;
- domain-тесты построения паттернов `1-2-1` и `1-2-3-2-1`;
- domain-тесты транспозиции вверх/вниз;
- domain-тесты определения близости к границам диапазона;
- repository-тесты сохранения и чтения последнего диапазона;
- widget-тесты основных состояний:
  - экран определения нижней ноты;
  - экран результата;
  - выбор упражнения;
  - предупреждение у границы диапазона.

Перед завершением реализации:

- `flutter test` для модуля или workspace-сегмента;
- `flutter analyze` для изменённых пакетов.

## 14. Acceptance criteria

Фича считается готовой, если:

- при первом запуске пользователь проходит определение диапазона от нижней до верхней ноты;
- экран результата показывает ноты, частоты, клавиатуру, тип голоса и кнопки `Продолжить`/`Заново`;
- `Заново` запускает определение диапазона с начала;
- после `Продолжить` пользователь выбирает `Мычание` или `Тра-та-та`;
- оба упражнения запускаются и отображают правильные паттерны;
- проходы чередуют `Поём с голосом` и `Поём самостоятельно`;
- кнопка `Пропустить голос` переводит к самостоятельному проходу;
- упражнение транспонируется вверх и вниз;
- у границ диапазона появляются предупреждения и кнопки `Выше / ниже` и `Хватит`;
- `Хватит` завершает текущую сессию без ошибки;
- последний диапазон сохраняется и используется при следующем запуске;
- модуль подключается через публичный entry point и не раскрывает внутренние `src/*` API.
